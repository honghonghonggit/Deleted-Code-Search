# 분류기 학습·검증 - val 100 (#86)

- 작성: 2026-10-11, 희수(hs). 숫자 원본: `docs/reports/classifier_val.json`
- **test 100 은 아직 돌리지 않았다.** 이 문서는 학습 300 / 검증 100 으로 방식을 고른 기록이다. test 는 성제가 H 를 기록한 뒤 한 번 돈다 (게이트 2 사전 등록, 아래 "test 실행")
- 정답은 `datasets/labeled_500.jsonl` 의 `final.reason_label` (2인 일치 350 + 제3자 판정 150, #166)

## 1. 요약

| 방식 | 버전 | val 정확도 | 95% 구간 (Wilson) |
|---|---|---:|---|
| 모두 UNK 라고 답하기 | - | 39.0% | - |
| 기준선 A (커밋 메시지 키워드) | `a1` | 40.0% | 30.9~49.8% |
| 기준선 B (LLM 직접 질의) | `b1` / deepseek-v4.1-flash | 53.0% | 43.3~62.5% |
| **우리 방식** | `r1+m2+c3` + deepseek-v4.1-flash | **59.0%** | 49.2~68.1% |

- **기준선 B 보다 6.0%p 높다. 게이트 2 ② "max(A, B) + 10%p" 에 val 에서는 못 미친다.** ① 의 상한 80% 와는 21%p 차이다
- 같은 100건에서 짝지어 보면 우리만 맞힌 것 21건, B 만 맞힌 것 15건이다 (정확 이항 검정 p = 0.41). **이 차이는 우연과 구별되지 않는다.** A 와는 29 : 10 (p = 0.003)
- val 은 방식을 고르는 데 여러 번 봤다 (§4). 그래서 59% 는 test 예측치로는 낙관 쪽이다

## 2. 최종 방식 (`classify/classifier.py`, `classify/model.py`)

1. **LLM 후보 (프롬프트 c3)** - 라벨러 화면(파일·함수·테스트 여부, 맥락 문장, 삭제 코드, 같은 파일 추가 헝크, 대체 코드)과 가이드 v3 판정 순서 요약을 주고 `라벨|근거` 한 줄을 받는다. 모델·설정은 #59 고정값 그대로 (`max_tokens` 256, `temperature` 0, 생각 과정 끔)
2. **모델 m2** - TF-IDF + 로지스틱 회귀(C = 10), **UNK 를 포함한 8종**. 특징은 맥락 문장 + 함수·파일 이름 + 화면 모양 낱말(PR·이슈·리뷰·테스트·추가 헝크·대체 코드 유무) + 추가 헝크
3. **점수 = 모델 확률 + 0.5 × [LLM 이 고른 라벨]**, 가장 높은 라벨. 동점이면 이유 문장이 받치는 라벨, 그다음 가이드 §11-1 우선순위
4. **규칙(r1)은 라벨을 고르지 않는다.** 근거 등급과 인용(EXPLICIT 원문)에만 쓴다

#84 와 달라진 것:

| | #84 (r1+m1+c1) | #86 (r1+m2+c3) | 왜 |
|---|---|---|---|
| UNK 를 정하는 곳 | "키워드 문장도 대체 코드도 없으면 UNK" 관문 | 모델·LLM 점수 | 관문이 걸린 81건 중 정답 UNK 는 56건, 정답 UNK 135건 중 79건은 관문을 통과했다 (train) |
| 규칙 키워드 표 | 라벨 점수에 1.0 | 없음 | 표가 BUG 를 98건(정답 6건) 내 train 교차 검증 0.46 → 0.33 |
| 모델 | UNK 제외 7종, 맥락만, class_weight balanced | UNK 포함 8종, + 화면 모양·추가 헝크, 가중치 없음 | 아래 표 |
| LLM 프롬프트 | c1 (정의 한 줄씩 + 맥락·삭제·대체 코드) | c3 | 아래 표 |
| LLM 가중치 | 1.0 (자리표시자) | 0.5 | 아래 표 |

## 3. 고른 과정 - 시도한 것 전부

고르는 기준은 **학습 300건 5겹 교차 검증(train-CV)** 이고, val 은 확인에 썼다. 시드 0 으로 섞은 같은 5겹을 모든 행에 쓴다.

| 시도 | train-CV | val | 결과 |
|---|---:|---:|---|
| 모두 UNK | 45.0% | 39.0% | 바닥 |
| 기준선 A | 37.7% | 40.0% | 규칙이라 train 값은 그대로 적용한 값 |
| 기준선 B | - | 53.0% | train 은 부르지 않았다 |
| #84 분류기 (LLM 없음) | 33.0% | 36.0% | 출발점 |
| #84, 규칙 표 0 / 0.5 | 46.0% / 36.7% | - | 규칙 표를 뺐다 |
| 모델만: 맥락 텍스트, UNK 포함 | 56.0% | - | |
| 모델만: + 화면 모양 | 58.3% | - | |
| 모델만: + 화면 모양 + 삭제 본문 | 56.3% | - | 버림 |
| **모델만: + 화면 모양 + 추가 헝크 (m2)** | **60.3%** | 52.0% | 채택 |
| 모델만: m2, class_weight balanced | 58.7% | - | 버림 |
| LLM 만 c1 | - | 52.0% | #59 고정 프롬프트 |
| LLM 만 c2 | 48.3% | 51.0% | FEAT 를 30건 냄 (정답 9) |
| m2 + c2, 가중치 0.5 | 63.3% | 59.0% | |
| **LLM 만 c3** | **61.7%** | 59.0% | c2 의 train 오류에서 규칙 추가 |
| **m2 + c3, 가중치 0.5 (최종)** | **67.3%** | **59.0%** | 가중치 0.4~0.7 이 65.3~67.3% 로 평평, 그 가운데 |
| m2 + c3 + 근거 관문 | 65.7% | - | 버림 |
| m2 + c3, LLM 답을 P(정답 \| LLM 답)으로 보정 | 최고 65.0% | - | 버림 |
| m2 + c3, LLM 답을 모델 특징으로 | 최고 62.7% | - | 버림 |

- **c2 → c3 는 train 의 오류만 보고 만들었다.** c2 는 train 에서 UNK 135건 중 34건을 DEAD, 30건을 FEAT 로 냈다. 사례는 (1) 테스트 함수가 지워졌다는 사실로 DEAD·FEAT, (2) "다른 저장소로 옮긴다"(langchain-community, ai21, embedchain) 를 FEAT, (3) 이동·재작성·revert 를 이유로 봤다. c3 는 가이드 §6.3.3·§6.4.4 를 그대로 옮겨 이 셋을 막았다. train 에서 LLM 단독 48.3% → 61.7%, UNK 예측 44 → 132건 (정답 135)
- 가중치는 0(모델만) 60.3%, 1 이상(LLM 답 그대로) 61.7% 이고 그 사이가 높다. 둘이 틀리는 곳이 다르다는 뜻이다
- **val 을 본 횟수**: 위 표의 val 칸 10개와, c2 조합 실험에서 함께 본 변형 3개(LLM 답을 모델 특징으로 56%·54%, 가중치 1.0 51%)다. c2 조합 숫자를 본 뒤에 c3 를 만들었지만, c3 를 만들 때 본 오류 사례는 train 이다

## 4. val 상세 - 우리 방식

| 이유 | 정답 수 | 예측 수 | precision | recall | F1 |
|---|---:|---:|---:|---:|---:|
| BUG | 1 | 0 | - | 0.000 | 0.000 |
| LIB | 2 | 4 | 0.000 | 0.000 | 0.000 |
| DEAD | 16 | 7 | 0.286 | 0.125 | 0.174 |
| DESIGN | 33 | 24 | 0.833 | 0.606 | 0.702 |
| FEAT | 9 | 16 | 0.312 | 0.556 | 0.400 |
| UNK | 39 | 49 | 0.653 | 0.821 | 0.727 |

정답 등급별 정확도: EXPLICIT 12/21 · INFERRED 15/40 · UNKNOWN 32/39

| 정답 \ 예측 | BUG | LIB | DEAD | DESIGN | FEAT | UNK |
|---|---:|---:|---:|---:|---:|---:|
| BUG | | | | 1 | | |
| LIB | | | | | | 2 |
| DEAD | | 3 | 2 | | 6 | 5 |
| DESIGN | | 1 | 1 | 20 | 2 | 9 |
| FEAT | | | 3 | | 5 | 1 |
| UNK | | | 1 | 3 | 3 | 32 |

- **DEAD 가 가장 약하다 (16건 중 2건).** 6건이 FEAT 로 갔다. train 에서도 같다 - "폐기한 기능의 테스트·내부 메서드", "V0 backend 제거" 같은 건을 사람은 DEAD 로, LLM 은 FEAT 로 본다. 가이드 §4 FEAT 정의("deprecation 주기를 마친 API 제거")만 보면 LLM 쪽이 가이드에 가깝다. **라벨과 가이드가 어긋나는 지점**이고, v3 를 마지막 개정으로 정했으므로(#162) 프롬프트로 라벨 쪽을 따라가게 하지 않았다
- UNK 는 recall 0.82 / precision 0.65 다. 정답 DESIGN 9건을 UNK 로 냈다
- PERF 0 · SEC 0 · BUG 1 · LIB 2 건이라 이 클래스들의 F1 은 말할 수 없다
- 등급: 우리 방식이 EXPLICIT 을 낸 건은 2건뿐이다 (정답 21). EXPLICIT 은 "고른 라벨의 키워드 문장이 함수를 이름으로 가리킬 때" 만 주는데, 키워드 문장이 아닌 곳에서 이유를 말하는 건을 못 잡는다. 등급은 게이트 판정에 쓰지 않아 이번에 고치지 않았다

## 5. 한계

- **val 100건, 여러 번 봤다.** 짝 비교에서 B 와의 차이가 우연과 구별되지 않는다 (§1)
- **기준선 B 와 우리 방식의 차이에는 맥락만 있는 게 아니다.** 우리 LLM 은 가이드 요약(`CANDIDATE_GUIDE`)도 받는다. B 는 사전 등록대로 `b1` 그대로다. "같은 가이드를 B 에 줬을 때" 는 재지 않았다
- **라벨러가 AI 보조 프롬프트(`docs/labeling_ai_prompt.md`)를 썼을 수 있다.** note 에 AI 를 적은 라벨은 1,000개 중 5개뿐이지만 쓴 사람이 다 적었는지는 모른다. c3 의 이유 정의·헷갈리는 쌍은 그 문서 문구를 줄여 썼으므로, 일치의 일부가 그 영향일 수 있다
- test 100 의 이유 분포(집계)는 #167 확인 때 봤다 (UNK 50건 - `docs/reports/labels_main500.md` 에도 있다). 개별 레코드·예측은 보지 않았고 선택에 쓰지 않았다
- LLM 한 건이 최근 10~30초다. 400건을 6개 프로세스로 나눠 15~35분 걸렸다 (무료 대기열에 따라 다르다)

## 6. test 실행 (고정 - 이 문서 뒤로 바꾸지 않는다)

- 방식: `r1+m2+c3`, `WEIGHT_LLM` 0.5, `REGULARIZATION_C` 10, LLM `deepseek-ai/deepseek-v4.1-flash`
- **test 에서는 학습+검증 400건으로 다시 학습한다** (`TRAIN_SPLITS`). 방식·값은 위 그대로다
- 순서: 성제가 H 를 기록 (#92) → 희수가 한 번에 돈다 (#87 기준선 A·B 와 같은 시점) → 캐시 커밋

```bash
python -m classify.classifier --records datasets/labels/main500_records.jsonl --labels datasets/labeled_500.jsonl --llm --split test --final-test --out <예측>
python -m classify.evaluate <예측> --split test --json docs/reports/<결과>.json
```

`--final-test` 없이 `--split test` 를 주면 분류기가 거부한다.
